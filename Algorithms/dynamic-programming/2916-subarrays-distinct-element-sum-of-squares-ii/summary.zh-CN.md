## 2. 题意理解（Problem Understanding）

给定整数数组 `nums`。对每个非空子数组，统计其中不同元素的个数，记为它的计数；返回所有子数组计数的平方和，结果对 $`10^9 + 7`$ 取模。

本题与 2913 的题意完全相同，只是数据范围从 $`n \leq 100`$ 扩大到 $`n \leq 10^5`$。

**示例**

- 输入：`nums = [1,2,1]`
- 输出：`15`
- 解释：六个子数组的计数依次为 1、1、1、2、2、2，平方和为 $`3 \cdot 1 + 3 \cdot 4 = 15`$。

**关键要求**

1. 子数组共有 $`n(n+1)/2`$ 个，约 $`5 \times 10^9`$，不能逐个枚举。
2. 求的是**计数的平方**之和，不是计数之和。
3. 答案需要取模，但线段树中的计数和最大约为 $`n^2 = 10^{10}`$，可以用 `int`（64 位）直接存储。

## 3. 初始思路（Initial Approach）

### 第一次想到：沿用 2913 的枚举

2913 的写法是固定左端点 `i`，右端点 `j` 向右扩展，用集合维护不同元素个数，每步累加 `len(s) * len(s)`。时间 O(n²)。

### 遇到的问题

$`n = 10^5`$ 时 O(n²) 约 $`10^{10}`$ 次操作，必然超时。需要不逐个枚举子数组，而是**批量更新**一批子数组的计数。

一个自然的疑问是：这类题常用 DP，为什么题解都在讲线段树？两者要的结果不一样吗？

### 思维转变

从：

> 固定左端点，逐个枚举右端点，计算每个子数组的计数。

转变为：

> 固定右端点 r，把所有以 r 结尾的子数组看成一个整体；右端点从 r−1 移到 r 时，只有一段连续的左端点计数加 1。

关键发现是：新元素 `nums[r]` 只会让「还没包含它」的子数组计数加 1，而这些子数组的左端点恰好构成一个区间 $`(p, r]`$，其中 p 是 `nums[r]` 上一次出现的位置。批量更新一个区间，正是线段树擅长的操作。

所以结果是一样的，算法仍然是 DP；线段树只负责让 DP 的每次转移变快。

## 4. 算法表达（Algorithm Specification）

**算法名称：** 按右端点递推 + 懒标记线段树（Right-Endpoint DP with a Lazy Segment Tree）

### 4.1 输入（Input）

$`A = \langle a_0, a_1, \ldots, a_{n-1} \rangle`$

满足：

- $`1 \leq n \leq 10^5`$
- $`1 \leq a_i \leq 10^5`$

### 4.2 输出（Output）

记 $`c(l, r)`$ 为子数组 $`a_l, \ldots, a_r`$ 中不同元素的个数。输出：

```math
\mathrm{ans} = \left( \sum_{0 \leq l \leq r < n} c(l, r)^2 \right) \bmod (10^9 + 7)
```

### 4.3 伪代码（Pseudocode）

```text
SUM-COUNTS(A)
    n ← length(A)
    T ← 长度为 n、初值全 0 的线段树，支持区间加与区间求和
    last ← 空映射            // 值 → 上一次出现的下标
    f ← 0
    ans ← 0

    for r ← 0 to n − 1
        p ← last[A[r]]，不存在时为 −1
        S ← T.SUM(p + 1, r)        // 先查询：此时位置 l 存的是 c(l, r−1)
        T.ADD(p + 1, r, 1)         // 再修改：位置 l 变为 c(l, r)
        f ← (f + 2·S + (r − p)) mod M
        ans ← (ans + f) mod M
        last[A[r]] ← r

    return ans
```

**状态定义**

- `T[l]`：处理完右端点 r 后，等于 $`c(l, r)`$；尚未作为左端点出现的位置（$`l > r`$）为 0。
- `f`：所有以 r 结尾的子数组的计数平方和，即 $`f(r) = \sum_{l=0}^{r} c(l, r)^2`$。
- `ans`：所有右端点不超过 r 的子数组的计数平方和。
- `p`：`A[r]` 在 r 之前最后一次出现的下标，没有出现过时为 −1。

### 4.4 正确性（Correctness）

**证明方法：引理 + 循环不变式**

#### 一、正确性依赖的关键条件

1. **计数的增量只有 0 或 1**：把 `A[r]` 接到子数组末尾，不同元素的个数要么不变，要么加 1。
2. **受影响的左端点构成区间**：计数加 1 的左端点恰好是 $`(p, r]`$。
3. **平方的增量可以由区间和表示**：$`(c+1)^2 - c^2 = 2c + 1`$，所以一段区间平方和的增量等于 2 倍区间和加区间长度。

**引理**：对 $`0 \leq l \leq r`$，记 $`c(r, r-1) = 0`$，则

```math
c(l, r) = c(l, r-1) + [\, l > p \,]
```

证明：`A[r]` 已经出现在 $`a_l, \ldots, a_{r-1}`$ 中，当且仅当这一段包含某个下标 $`q < r`$ 且 $`a_q = a_r`$，又当且仅当 $`l \leq p`$，因为 p 是其中最大的这样的下标。已出现时计数不变，否则加 1。

由引理得到 f 的转移：

```math
\begin{aligned}
f(r) &= \sum_{l=0}^{p} c(l, r-1)^2 + \sum_{l=p+1}^{r} \bigl( c(l, r-1) + 1 \bigr)^2 \\
     &= f(r-1) + 2 \sum_{l=p+1}^{r} c(l, r-1) + (r - p)
\end{aligned}
```

其中 $`c(r, r-1) = 0`$ 恰好让新子数组 $`[r, r]`$ 贡献 $`1^2 = 1`$，不需要单独处理。

#### 二、正确性证明

**循环不变式（Loop Invariant）**

在第 r 次迭代结束时：

**不变式 I：线段树的含义**

对 $`l \leq r`$ 有 $`T[l] = c(l, r)`$；对 $`l > r`$ 有 $`T[l] = 0`$。

**不变式 II：部分结果**

$`f = f(r) \bmod M`$，且 $`\mathrm{ans} = \sum_{r'=0}^{r} f(r') \bmod M`$。`last` 记录了 $`a_0, \ldots, a_r`$ 中每个值最后一次出现的下标。

**初始化（Initialization）**

循环开始前（视为 $`r = -1`$），T 全为 0，`f = ans = 0`，`last` 为空。没有任何子数组，不变式成立。

**保持（Maintenance）**

假设第 $`r-1`$ 次迭代后不变式成立。第 r 次迭代中：

- 查询时 T 尚未修改，由不变式 I，`S` 等于 $`\sum_{l=p+1}^{r} c(l, r-1)`$，其中位置 r 的值为 0，对应 $`c(r, r-1) = 0`$。
- 对 $`[p+1, r]`$ 加 1 后，由引理，所有 $`l \leq r`$ 的位置都变为 $`c(l, r)`$；$`l > r`$ 的位置未被修改，仍为 0。不变式 I 保持。
- 由转移式，新的 `f` 等于 $`f(r)`$；`ans` 累加 `f` 后包含了所有右端点不超过 r 的子数组。`last[A[r]]` 更新为 r。不变式 II 保持。

**终止（Termination）**

循环执行 n 次后结束，此时 $`r = n - 1`$。每个子数组恰好有一个右端点，所以 `ans` 等于全部子数组的计数平方和取模。

#### 三、结论

引理把「哪些子数组的计数变了」化为一个区间，平方展开把「平方和怎么变」化为该区间的和。循环不变式保证线段树始终存着当前右端点下每个左端点的计数，因此算法对所有合法输入正确。

### 4.5 复杂度分析（Complexity Analysis）

设输入规模为 $`n`$。

**时间复杂度：O(n log n)**

循环执行 n 次，每次一次区间查询和一次区间修改，各为 O(log n)；`last` 的读写为均摊 O(1)。

**空间复杂度：O(n)**

线段树的和数组与懒标记数组各需 4n 个位置；`last` 最多存 n 个键。值域只有 $`10^5`$，`last` 也可以换成定长数组。

## 5. 思维难点（Learning Notes）

### 难点一：这是 DP 还是线段树？为什么不能只用 DP？

一开始的疑问是：既然能写出 f(r) 由 f(r−1) 转移的式子，为什么不直接 DP，还要线段树？两种做法求的结果不一样吗？

**理解过程**

结果完全一样，算法也确实是 DP。问题出在转移式里的 $`\sum_{l=p+1}^{r} c(l, r-1)`$：

- 它要的是**一段左端点**上计数的和，而 p 每一步都不同，查询的区间是任意的；
- 每一步之后，这一段的计数还要整体加 1。

所以要保存的状态是整个数组 $`c(\cdot, r)`$，无法压缩成 O(1) 个标量。用普通数组维护，每次区间加和区间求和都是 O(n)，总体又回到 O(n²)。线段树把这两个操作降到 O(log n)。

对比 [2262. 字符串的总引力](https://leetcode.cn/problems/total-appeal-of-a-string/)：它求的是 $`\sum c(l, r)`$，没有平方。同样推导，增量就是区间长度 $`r - p`$，不依赖 c 本身，一个标量就能递推，O(n) 的纯 DP 即可。**平方是非线性的**，$`(c+1)^2`$ 的增量 $`2c+1`$ 依赖 c，所以必须把每个 c 都维护起来。

**可迁移思维：** 写出 DP 转移后，检查增量需要的信息能否用几个标量概括。能，就是纯 DP；不能，就需要数据结构来维护状态。

### 难点二：线段树是算法还是数据结构？

**理解过程**

两者不在同一层面：

- **DP 决定「算什么」**：建模、定义状态 f(r)、写出转移式，正确性也由它保证。
- **线段树决定「怎么算得快」**：它只实现「区间加 1」「区间求和」两个操作。把线段树换成普通数组，答案仍然正确，只是变慢。

这种组合通常称为**数据结构优化 DP**。同类的还有单调队列优化 DP、树状数组优化最长递增子序列。另一方面，线段树也常与扫描线、贪心、离线查询搭配，并不专属于 DP。因此本题归入动态规划分类，线段树作为辅助分类与标签。

**可迁移思维：** 遇到「DP + 某数据结构」的题解，先剥掉数据结构，写出朴素的 O(n²) 转移；再看瓶颈是哪种操作，选能加速这种操作的结构。

### 难点三：为什么先查询、后修改？

**理解过程**

转移式需要的是**旧值** $`c(l, r-1)`$ 的和。先执行区间加，查询到的就是 $`c(l, r)`$ 的和，比正确值多出区间长度 $`r - p`$，答案会偏大。

查询区间包含位置 r 也没有问题：该位置在本轮之前恰好为 0，对应 $`c(r, r-1) = 0`$，新子数组 $`[r, r]`$ 的贡献 1 由 $`r - p`$ 这一项给出。

**可迁移思维：** 用「旧状态 + 增量」写转移时，先读出转移需要的旧值，再写入新状态。

## 6. 可迁移知识（Key Takeaways）

本题总结出以下可复用的方法：

1. **Right-endpoint sweep（按右端点递推）**：统计所有子数组时，固定右端点，把以它结尾的全部子数组作为一个整体状态，从 r−1 转移到 r。
2. **Last occurrence boundary（上一次出现位置界定影响区间）**：新元素只影响左端点在 $`(p, r]`$ 的子数组。同样的界定方式也出现在 828、2262 等「子数组 / 子串中不同元素」的计数题中。
3. **Data-structure-optimized DP（数据结构优化 DP）**：转移需要对一段状态做区间修改与区间查询时，用线段树或双树状数组维护状态数组。
4. **Expanding a nonlinear increment（展开非线性增量）**：$`(c+1)^2 = c^2 + 2c + 1`$ 把平方的变化化为一次项之和；更高次方需要同时维护更多阶的和，例如三次方还需要维护 $`\sum c^2`$。

这些方法适用于「对所有子数组求某个统计量的和」，且每次扩展右端点时受影响的左端点构成连续区间的问题。若受影响的左端点不连续，或增量无法展开成可维护的区间统计量，就需要别的思路。
