## 2. 题意理解（Problem Understanding）

给定一个有效括号字符串，删除每个原语括号字符串最外层的括号。

例如：

- 输入：`(()())(())`
- 输出：`()()()`

关键要求：

1. 输入保证是有效括号**字符串**。
2. 原语是非空且不能拆成两个非空有效括号字符串拼接的有效括号字符串。
3. 只删除每个原语的最外层括号，内部括号保持不变。

## 3. 初始思路（Initial Approach）

### 第一次想到：Stack（栈）

看到括号问题时，首先想到使用栈。

原因是栈适合处理括号匹配和嵌套结构，可以记录尚未匹配的左括号。

但是重新分析题目后发现：

**这道题并不要求找到每一个括号的匹配对象，只需要判断括号是否处于最外层。**

因此，栈保存的匹配信息超过了题目的实际需求。

可以进一步简化为一个变量 `depth`，表示当前括号嵌套深度。

### 思维转变

从：

> 如何记录并匹配每个括号？

转变为：

> 如何判断当前括号是否属于最外层？

前者关注具体元素的匹配关系，后者关注当前状态。

这使得辅助状态从栈简化为单个计数器。

## 4. 算法表达（Algorithm Specification）

## 4. 算法表达（Algorithm Specification）

**算法名称：** 深度计数法（Depth Counting）

### 4.1 输入（Input）

一个长度为 n 的有效括号字符串：

`s = <s₁, s₂, ..., sₙ>`

满足：

- 每个字符属于 `{ '(', ')' }`。
- 对于任意前缀，左括号数量不少于右括号数量。
- 整个字符串中左右括号数量相等。

### 4.2 输出（Output）

一个字符串：

`s' = <s'₁, s'₂, ..., s'ₘ>`

设输入可以唯一分解为若干原语：

`s = P₁ + P₂ + ... + Pₖ`

输出满足：

`s' = inner(P₁) + inner(P₂) + ... + inner(Pₖ)`

其中 `inner(P)` 表示删除原语 P 的第一个左括号和最后一个右括号后得到的字符串。

### 4.3 伪代码（Pseudocode）

```text
REMOVE-OUTER-PARENTHESES(s)
    res ← ""
    depth ← 0

    for each ch in s
        if ch == '('
            if depth > 0
                APPEND(res, ch)
            depth ← depth + 1
        else
            depth ← depth - 1
            if depth > 0
                APPEND(res, ch)

    return res
```

**状态定义**

- `depth`：已经扫描的字符中，尚未匹配的左括号数量。
- `res`：已经扫描的字符中，需要保留的内部括号，按原顺序排列。

### 4.4 正确性（Correctness）

**证明方法：循环不变式（Loop Invariant）**

#### 一、正确性依赖的关键条件

本算法的正确性依赖于以下三个性质：

1. **有效括号性质**：任意前缀的括号深度非负，完整原语结束时深度回到 0。
2. **状态对应关系**：`depth` 始终准确表示当前未匹配的左括号数量。
3. **最外层判断规则**：
   - 左括号处理前 `depth = 0`，当且仅当它是某个原语最外层的左括号。
   - 右括号处理后 `depth = 0`，当且仅当它是某个原语最外层的右括号。

因此，通过判断相应时刻的深度，就能够决定是否保留当前字符。

#### 二、循环不变式

在每次循环开始时，假设已经处理前 i 个字符，以下性质保持不变：

**不变式 I：深度正确性**

`depth = 已处理前缀的左括号数量 - 右括号数量`

即 `depth` 始终代表当前未匹配的左括号数量。

**不变式 II：结果正确性**

`res` 恰好包含已处理前缀中所有不属于原语最外层的括号，且字符相对顺序与输入一致。

#### 三、初始化（Initialization）

循环开始前：

- 尚未处理任何字符。
- `depth = 0`。
- `res = ""`。

空前缀中左括号与右括号数量均为 0，因此不变式 I 成立。

空前缀不存在需要保留的括号，因此不变式 II 成立。

所以循环不变式在第一次迭代前成立。

#### 四、保持（Maintenance）

假设循环开始时两个不变式均成立。

根据当前字符，分两种情况讨论。

**情况一：当前字符为 `(`**

- 当 `depth = 0` 时，该左括号开启一个新的原语，属于最外层，不加入 `res`。
- 当 `depth > 0` 时，该左括号处于原语内部，需要加入 `res`。
- 最后执行 `depth + 1`，使其继续准确表示未匹配左括号数量。

因此，两个不变式在本次迭代后仍然成立。

**情况二：当前字符为 `)`**

- 首先执行 `depth - 1`，表示关闭当前一层括号。
- 当更新后 `depth = 0` 时，该右括号结束当前原语，属于最外层，不加入 `res`。
- 当更新后 `depth > 0` 时，该右括号仍处于原语内部，需要加入 `res`。

由于输入是有效括号字符串，处理右括号前深度必然大于 0，因此更新后的深度仍然非负且正确。

两个不变式继续成立。

综上，循环不变式在每次迭代后均保持成立。

#### 五、终止（Termination）

循环遍历完整个字符串后：

- 根据不变式 I，由于输入是有效括号字符串，`depth = 0`。
- 根据不变式 II，`res` 包含输入中所有非原语最外层的括号，且保持原始顺序。

因此，`res` 恰好是删除每个原语最外层括号后的字符串。

**算法正确。**

### 4.5 复杂度分析（Complexity Analysis）

设输入字符串长度为 n。

**时间复杂度：O(n)**

算法对每个字符执行一次遍历，每次迭代只涉及常数次判断、状态更新和追加操作。

因此总时间复杂度为 O(n)。

**空间复杂度：O(n)**

- `depth` 占用 O(1) 空间。
- `res` 在最坏情况下保存 O(n) 个字符。

因此总空间复杂度为 O(n)。

若不计算输出缓冲区，则额外辅助状态的空间复杂度为 O(1)。


## 5. 思维难点（Learning Notes）

### 难点一：什么时候不需要栈？

最初看到括号问题，会自然联想到栈。

但选择数据结构前，应先判断题目需要保存什么信息。

如果需要知道括号的具体匹配关系，栈通常很合适。

如果只需要知道当前嵌套层数，那么计数器可能足够。

**可迁移思维：不要因为问题具有某种典型特征，就直接使用对应的数据结构；先判断实际需要的信息。**

### 难点二：为什么判断和更新的顺序不同？

这是本题最需要理解的地方。

对于 `(`，需要使用进入当前层之前的 `depth`；对于 `)`，需要使用关闭当前层之后的 `depth`。

所以左右括号虽然都遵循“只保留内部括号”的原则，但操作顺序不同。

进一步归纳：

**先定义状态变量的准确含义，再判断条件需要的是更新前还是更新后的状态。**

这比单纯记忆“左括号先判断，右括号先更新”更有价值。

## 6. 可迁移知识（Key Takeaways）

本题总结出三个可复用的方法：

1. **Information Reduction（信息简化）**：只维护解决问题所需要的最小信息，不必保存全部中间细节。
2. **State Invariant（状态不变量）**：明确变量在每次循环的特定时刻表示什么。
3. **Condition-Update Order（判断与更新顺序）**：状态更新与条件判断的顺序应由状态定义决定，而不是由代码书写习惯决定。

尤其是第三点，可以用于其他涉及计数器、嵌套结构或状态变化的模拟问题。
