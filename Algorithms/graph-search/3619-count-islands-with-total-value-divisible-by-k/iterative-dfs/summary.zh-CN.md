## 4. 算法表达（Algorithm Specification）

**算法名称：** 显式栈深度优先搜索（Iterative Depth-First Search with an Explicit Stack）

本节下标从 0 开始。

### 4.1 输入（Input）

与递归版相同：网格 $`\mathrm{grid}`$（$`m \times n`$）和正整数 $`k`$。把网格看作无向图 $`G = (V, E)`$，$`V`$ 是全部正数格，上下左右相邻的两个陆地格之间连边，顶点权值 $`w(v) = \mathrm{grid}[v]`$。

### 4.2 输出（Output）

记连通分量 $`C`$ 的总价值为

```math
S(C) = \sum_{v \in C} w(v)
```

输出 $`\mathrm{res}`$ 是满足 $`S(C) \bmod k = 0`$ 的连通分量 $`C`$ 的个数。

### 4.3 伪代码（Pseudocode）

```text
COUNT-ISLANDS(grid, k)
    visited ← m × n 的布尔数组，全部为 false
    res ← 0
    for r ← 0 to m - 1
        for c ← 0 to n - 1
            if grid[r][c] ≠ 0 and not visited[r][c]
                S ← 空栈
                PUSH(S, (r, c))
                visited[r][c] ← true          ▷ 入栈时标记
                total ← 0
                while S 非空
                    (x, y) ← POP(S)
                    total ← total + grid[x][y]
                    for each (nx, ny) in {(x+1, y), (x-1, y), (x, y-1), (x, y+1)}
                        if 0 ≤ nx < m and 0 ≤ ny < n
                                and grid[nx][ny] ≠ 0 and not visited[nx][ny]
                            PUSH(S, (nx, ny))
                            visited[nx][ny] ← true
                if total mod k == 0
                    res ← res + 1
    return res
```

**状态定义**

- `visited[x][y]`：格子已经被发现，即已经入过栈。
- `S`：已发现但还没处理（还没累加、还没检查邻居）的格子。
- `total`：当前这座岛中已出栈的格子的值之和。
- `res`：已经处理完的岛屿中，总价值能被 $`k`$ 整除的个数。

### 4.4 正确性（Correctness）

**证明方法：内层循环的循环不变式 + 外层循环的循环不变式**

#### 一、正确性依赖的关键条件

1. **入栈时标记**：一个格子只在 `visited` 为 false 时入栈，入栈的同时置为 true，之后不会再变回 false。所以**每个格子至多入栈一次**，也就至多出栈、累加一次。
2. **只沿陆地扩展**：只有陆地格会入栈，而且新入栈的格子一定与某个已出栈的格子相邻，所以一次搜索不会走出起点所在的岛。
3. **连通性**：岛屿 $`C`$ 中任意两格之间有一条全在 $`C`$ 内的路径。

#### 二、正确性证明

**内层循环的不变式**

固定一次搜索，起点为 $`s`$，它所在的岛为 $`C`$。把 $`C`$ 中的格子分成三类：已出栈的集合 $`T`$、当前在栈中的集合 $`P`$、其余尚未发现的格子。每次检查 `while` 条件时：

**不变式 I：分类不重不漏**

本次搜索中入过栈的格子恰好是 $`T \cup P`$，$`T \cap P = \varnothing`$，且 $`T \cup P \subseteq C`$。

**不变式 II：累加正确**

`total` $`= \sum_{v \in T} w(v)`$。

**不变式 III：已出栈格子的邻居都已发现**

$`T`$ 中每个格子的每个陆地邻居都已入过栈，即属于 $`T \cup P`$。

**初始化**：第一次检查前，$`T = \varnothing`$，$`P = \{s\}`$，`total` $`= 0`$。由外层循环的不变式（见下文），$`s`$ 所在的岛此前没有格子被发现，所以三条不变式都成立。

**保持**：一次迭代弹出格子 $`v`$，把它从 $`P`$ 移到 $`T`$，累加 $`w(v)`$，不变式 II 保持。接着检查 $`v`$ 的四个邻居：越界、是水或已发现的邻居不处理；其余邻居是 $`C`$ 中尚未发现的陆地格，入栈并标记，加入 $`P`$。所以 $`v`$ 的所有陆地邻居此时都在 $`T \cup P`$ 中，不变式 III 对新加入 $`T`$ 的 $`v`$ 成立，对原有的 $`T`$ 中格子也继续成立。新入栈的格子都是 $`C`$ 中未发现的格子，不变式 I 保持。

**终止**：由关键条件 1，每个格子至多入栈一次，所以内层循环至多迭代 $`\lvert C \rvert`$ 次后栈空。此时 $`P = \varnothing`$。

假设 $`T \ne C`$。取 $`C`$ 中一个不在 $`T`$ 中的格子 $`u`$，以及一条从 $`s`$ 到 $`u`$ 且全在 $`C`$ 内的路径。$`s \in T`$，路径上第一个不在 $`T`$ 中的格子是 $`T`$ 中某个格子的陆地邻居，由不变式 III 它在 $`T \cup P = T`$ 中，矛盾。所以 $`T = C`$，由不变式 II，`total` $`= S(C)`$。

**外层循环的不变式**

按行优先顺序扫描格子。在检查格子 $`(r, c)`$ 之前：

- **不变式 A：每座岛要么全部已发现，要么全部未发现**。若岛 $`C`$ 有格子排在 $`(r, c)`$ 之前，则 $`C`$ 的格子全部 `visited`；否则全部未 `visited`。
- **不变式 B：计数正确**。`res` 等于全部已发现的岛中，满足 $`S(C) \bmod k = 0`$ 的个数。

初始化时没有格子被发现，`res` $`= 0`$，成立。

保持：若当前格是水或已发现，不做任何事，两条不变式保持。否则当前格是陆地且未发现，由不变式 A，它所在的岛 $`C`$ 全部未发现。由上面的内层循环分析，搜索结束时恰好发现了 $`C`$ 的全部格子，`total` $`= S(C)`$，按条件更新 `res`，两条不变式保持。

终止：扫描完所有格子后，每座岛都已全部发现，`res` 就是答案。

#### 三、结论

每座岛在扫描到它的第一个格子时被完整搜索一次，搜索结束时 `total` 恰好是这座岛的总价值；此后这座岛的格子都已标记，不会再被搜索。因此算法对所有合法输入返回正确答案。

### 4.5 复杂度分析（Complexity Analysis）

设网格有 $`m`$ 行 $`n`$ 列。

**时间复杂度：$`\Theta(mn)`$**

初始化 `visited` 需要 $`\Theta(mn)`$。外层双重循环执行 $`mn`$ 次。由关键条件 1，每个陆地格至多入栈、出栈各一次，每次出栈检查 4 个邻居，都是常数时间。合计 $`\Theta(mn)`$。

**空间复杂度：$`\Theta(mn)`$**

- `visited` 数组恰好 $`mn`$ 个布尔值，不论网格内容如何都要分配，所以是 $`\Theta(mn)`$。
- 栈中的格子互不相同（每格至多入栈一次），所以栈的大小不超过当前岛的格子数，至多 $`mn`$。
- 不修改输入 `grid`。

切片在 `append` 时可能扩容，单次扩容需要复制，但摊还到每次 `append` 是 $`O(1)`$，不影响总时间。

**整数范围**

与递归版相同：岛屿总和至多 $`10^{11}`$，需要 64 位整数。Go 的 `int` 在 64 位平台上是 64 位。

## 5. 思维难点（Learning Notes）

### 难点一：为什么要在入栈时标记，而不是出栈时？

**理解过程**

`visited` 的含义是“已经发现”，而不是“已经处理完”。入栈时标记，保证每个格子至多入栈一次，于是至多累加一次，栈的大小也不超过岛的格子数。

如果改成出栈时标记，同一个格子在出栈前可能被多个邻居看到，每个邻居都会把它压一次栈。只要岛内有环（例如 $`2 \times 2`$ 的方块），就会出现这种情况，导致：

- 若出栈时不检查是否已访问，同一格的值会被累加多次，答案出错；
- 若出栈时检查并跳过，答案是对的，但入栈次数会达到边数的量级，栈也更大。

**可迁移思维：** 用栈或队列做图搜索时，“标记”应该与“加入待处理集合”同时发生。BFS 也是同样的道理：入队时标记。

### 难点二：这真的是深度优先搜索吗？

**理解过程**

这种写法在弹出一个格子时，会把它的所有未发现邻居一次性压栈并标记。它和递归 DFS 的访问顺序不完全相同：递归 DFS 进入一个邻居后，会先把那个邻居能到的地方走完，再回来看下一个邻居；而这里，后面的邻居在一开始就被标记了，之后即使从别的路径先走到它附近，也不会再“发现”它一次。

所以它不保证得到 CLRS §22.3 意义下的 DFS 发现顺序，也不能直接用来求发现时间、完成时间或做边的分类。但本题只需要“找出整个连通分量”，任何不重不漏的搜索顺序都可以，正确性证明（4.4）也没有用到访问顺序。如果需要严格的 DFS 顺序，可以在栈中保存“格子 + 下一个要检查的方向”，模拟递归的调用帧。

**可迁移思维：** 先想清楚题目需要搜索的哪种性质。只需要连通性时，DFS、BFS、显式栈都可以互换；需要发现时间、拓扑序等依赖顺序的性质时，才必须严格模拟递归。

### 难点三：显式栈换来了什么？

**理解过程**

递归版在全陆地网格上递归深度会达到 $`mn`$。Go 的栈会自动增长，所以两种写法在 Go 中都能通过；但在默认栈较小的语言里，递归版可能栈溢出。显式栈把“调用栈”放到堆上的切片中，深度只受内存限制。代价是要多写 `visited` 数组和栈的维护代码。

另外，本解法用 `visited` 而不是把格子置 0，所以不会修改输入。

**可迁移思维：** 递归改迭代的通用做法是用栈保存“还没做完的工作”。只关心访问到哪些顶点时，栈里只放顶点就够了；需要在子调用返回后继续做事时，还要保存当前进行到哪一步。

## 6. 可迁移知识（Key Takeaways）

本题总结出以下可复用的方法：

1. **Recursion to Iteration with an Explicit Stack（用显式栈把递归改写为迭代）**：在本题中，切片充当栈，保存已发现、待处理的格子，避免了递归深度达到 $`mn`$。适用于递归深度可能很大的搜索、树遍历等问题。限制：如果子调用返回后还要继续处理（如求完成时间、后序遍历），栈中还要保存进度。
2. **Mark on Discovery（发现时标记）**：在本题中，入栈的同时设置 `visited`，保证每个格子至多入栈一次。适用于所有基于栈或队列的图搜索。
3. **Implicit Graph（隐式图）**：在本题中，网格格子是顶点，上下左右相邻是边，邻居用坐标偏移即时计算。条件是邻居能以常数时间枚举。
4. **Aggregate per Connected Component（按连通分量聚合）**：在本题中，搜索时累加分量内的权值和，栈空后对整个分量判断一次。条件是聚合量能在遍历中逐个顶点累积。
5. **Closure Argument for Search Completeness（用闭包性质证明搜索完整）**：在本题中，“已出栈格子的陆地邻居都已发现”加上栈空，推出已出栈集合对邻接封闭，再由连通性推出它就是整座岛。适用于证明各种 BFS、DFS 变体都能找出整个连通分量。
