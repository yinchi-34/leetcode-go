## 2. 题意理解（Problem Understanding）

给定二叉树的根结点 `root`，按**中序**返回所有结点的值：对每个结点，先输出它整棵左子树的值，再输出它自己，最后输出整棵右子树的值。

**示例**

- 输入：`root = [1,null,2,3]`
- 输出：`[1,3,2]`

根 1 没有左孩子，所以先输出 1；接着处理右子树 2：2 的左孩子 3 先输出，然后才是 2。

- 输入：`root = []`，输出：`[]`
- 输入：`root = [1]`，输出：`[1]`

**关键要求**

1. 输入约束：结点数在 $`[0, 100]`$ 内，$`-100 \le \mathrm{Node.val} \le 100`$。
2. 输出顺序完全由树的形状决定，与结点值的大小无关；只有当树是二叉搜索树时，中序序列才恰好有序。
3. 边界：空树返回空列表；树可能退化成一条链。
4. 进阶：题目指出递归写法很简单，问能否用迭代完成。迭代写法见[显式栈解法](../iterative/summary.zh-CN.md)。

## 4. 算法表达（Algorithm Specification）

**算法名称：** 递归中序遍历（Recursive Inorder Traversal）

### 4.1 输入（Input）

一棵二叉树 $`T`$，按递归方式定义：$`T`$ 要么是空树 $`\varnothing`$，要么是三元组 $`(r, L, R)`$，其中 $`r`$ 是根结点，$`L`$、$`R`$ 分别是左、右子树（也是二叉树）。

记 $`\lvert T \rvert`$ 为 $`T`$ 的结点数，满足：

- $`0 \le \lvert T \rvert \le 100`$；
- 输入确实是一棵树：除根外每个结点只有一个父结点，沿孩子指针走不会回到已经经过的结点。所以 $`L`$、$`R`$ 互不相交且都不含 $`r`$，$`\lvert T \rvert = 1 + \lvert L \rvert + \lvert R \rvert`$。

### 4.2 输出（Output）

用 $`\cdot`$ 表示序列拼接，$`\langle\rangle`$ 表示空序列。定义 $`T`$ 的**中序序列**

```math
\mathrm{in}(T) =
\begin{cases}
\langle\rangle, & T = \varnothing \\
\mathrm{in}(L) \cdot \langle r.\mathrm{val} \rangle \cdot \mathrm{in}(R), & T = (r, L, R)
\end{cases}
```

输出 $`\mathrm{in}(T)`$。由定义和 4.1 中的 $`\lvert T \rvert = 1 + \lvert L \rvert + \lvert R \rvert`$，对结点数归纳可知 $`\mathrm{in}(T)`$ 恰好包含每个结点的值各一次，长度为 $`\lvert T \rvert`$。

### 4.3 伪代码（Pseudocode）

```text
INORDER(x)                              ▷ x 是子树的根，可能为 NIL
    if x == NIL
        return ⟨⟩
    res ← INORDER(x.left)
    res ← res · ⟨x.val⟩
    res ← res · INORDER(x.right)
    return res
```

代码中先建空切片 `res`，再依次 `append` 左子树结果、根的值和右子树结果，与伪代码等价。`x == NIL` 时代码返回空切片 `[]int{}` 而不是 `nil`，两者长度都是 0，对拼接没有区别。

**状态定义**

- `x`：当前子树的根；`x == NIL` 表示空子树。
- `res`：当前调用正在拼出的序列，返回时等于以 `x` 为根的子树的中序序列。

### 4.4 正确性（Correctness）

**证明方法：对结点数的强归纳（结构归纳）**

#### 一、正确性依赖的关键条件

1. **输入是一棵树**（题目条件）：$`\lvert L \rvert, \lvert R \rvert < \lvert T \rvert`$，递归规模严格变小，所以一定终止，归纳也能进行。
2. **算法与定义同构**：伪代码的两个分支与 $`\mathrm{in}`$ 定义的两个分支一一对应，空树对应 $`\langle\rangle`$，非空树对应“左 · 根 · 右”的拼接。
3. **递归调用互不干扰**：每次调用只读取自己子树中的结点，不修改任何结点，返回的是新建的切片，所以左、右两次调用的先后与结果无关。

#### 二、正确性证明

**定理。** 对任意满足 4.1 条件的二叉树 $`T`$，`INORDER(T)` 终止并返回 $`\mathrm{in}(T)`$。

*证明*：对 $`n = \lvert T \rvert`$ 做强归纳。

**基础（$`n = 0`$）**：$`T = \varnothing`$，`x == NIL` 成立，返回 $`\langle\rangle = \mathrm{in}(\varnothing)`$。

**归纳步（$`n \ge 1`$）**：假设对所有结点数小于 $`n`$ 的树结论成立。$`T = (r, L, R)`$ 非空，跳过基础分支。由关键条件 1，$`\lvert L \rvert, \lvert R \rvert \le n - 1`$，由归纳假设，`INORDER(x.left)` 终止并返回 $`\mathrm{in}(L)`$，`INORDER(x.right)` 终止并返回 $`\mathrm{in}(R)`$。三步拼接后

```math
\mathrm{res} = \mathrm{in}(L) \cdot \langle r.\mathrm{val} \rangle \cdot \mathrm{in}(R) = \mathrm{in}(T)
```

最后一个等号就是 $`\mathrm{in}`$ 的定义。∎

#### 三、结论

空树返回空序列；非空树的中序序列按定义归结为两棵更小子树的中序序列，归纳假设保证这两个序列已经算对，拼接顺序与定义一致。因此算法对所有合法输入返回正确的中序序列。

### 4.5 复杂度分析（Complexity Analysis）

设 $`n = \lvert T \rvert`$。对结点 $`u`$，记 $`d(u)`$ 为 $`u`$ 的深度（根到 $`u`$ 的边数，根为 0），$`T_u`$ 为以 $`u`$ 为根的子树，$`h`$ 为树的最大深度（按结点数计，与 104 题相同，空树为 0）。

**调用次数：$`2n + 1`$**

每个结点恰好作为一次非空调用的参数（根由外部调用，其余结点由唯一的父结点调用）；空调用对应空孩子指针，$`n \ge 1`$ 时有 $`n + 1`$ 个，$`n = 0`$ 时只有 1 次。共 $`2n + 1`$ 次。

**时间复杂度：$`\Theta(n + \sum_u d(u))`$，介于 $`\Theta(n \log n)`$ 与 $`\Theta(n^2)`$ 之间**

除了常数开销，每次调用的主要代价是**复制**：结点 $`u`$ 的调用把左、右子树返回的切片逐个元素复制进自己的 `res`，再追加 1 个自己的值，共写入 $`\lvert T_u \rvert`$ 个元素。所以所有调用写入的元素总数是

```math
\sum_{u} \lvert T_u \rvert = \sum_{v} \bigl(d(v) + 1\bigr) = n + \sum_{v} d(v)
```

第一个等号交换求和顺序：结点 $`v`$ 属于 $`T_u`$ 当且仅当 $`u`$ 是 $`v`$ 自己或 $`v`$ 的祖先，这样的 $`u`$ 恰有 $`d(v) + 1`$ 个。换句话说，每个值在它自己和它的每个祖先处各被复制一次。`append` 扩容时的额外复制按 CLRS §17.4 动态表的摊还分析只增加常数倍。

- **最坏情况**：树退化成一条链，深度为 $`0, 1, \ldots, n-1`$，总和 $`n(n-1)/2`$，时间 $`\Theta(n^2)`$。
- **最好情况**：完全二叉树，深度之和为 $`\Theta(n \log n)`$，时间 $`\Theta(n \log n)`$。

本题 $`n \le 100`$，所以实际运行没有任何问题；但同样的写法用在 $`10^5`$ 个结点的链上就会做约 $`5 \times 10^9`$ 次复制。把结果切片作为参数（或闭包变量）传下去、访问结点时只 `append` 一次，就能回到 $`\Theta(n)`$，这也是 CLRS §12.1 INORDER-TREE-WALK 的做法：访问结点时直接输出，不返回子序列。

**空间复杂度：额外 $`O(n)`$，输出 $`\Theta(n)`$**

- **递归栈**：最深时从根走到某片叶子再多一次空调用，深度 $`h + 1`$，即 $`\Theta(h)`$，最坏 $`\Theta(n)`$。
- **同时存活的中间切片**：任一时刻，只有当前递归路径上的调用持有尚未返回的 `res`，它们分别装着互不相交的子树的值，总长不超过 $`n`$。

合计额外空间 $`O(n)`$（不计等待垃圾回收的旧切片）。输出本身占 $`\Theta(n)`$。

## 5. 思维难点（Learning Notes）

### 难点一：返回切片再拼接，代价藏在哪里？

代码看起来每个结点只做了三次 `append`，很容易估成 $`O(n)`$。

**理解过程**

`append(res, child...)` 不是常数时间，它要把 `child` 的每个元素复制一遍。一个值从叶子一路被返回到根，每经过一层就被复制一次，所以总复制量是“每个值的深度加 1”之和（§4.5）。链状树上这就是 $`1 + 2 + \cdots + n = \Theta(n^2)`$。

**可迁移思维：** 估计递归的时间时，不能只数调用次数，还要看每次调用合并子结果的代价。“返回新容器再合并”的递归，总代价是每个元素被合并的次数之和；要避免这种代价，就把一个共享的结果容器传下去，让每个元素只写入一次。

### 难点二：中序序列和“有序”是什么关系？

**理解过程**

中序序列只由树的形状决定。对一般的二叉树，中序序列可以是任意顺序（例如 `[1,null,2,3]` 的结果是 `[1,3,2]`）。只有当树满足二叉搜索树性质（左子树的值都不大于根，右子树的值都不小于根）时，中序序列才按非降序排列，这正是 CLRS 定理 12.1 前后的讨论。测试中的 BST 用例检查的就是这一点。

**可迁移思维：** “中序 = 有序”是二叉搜索树的性质，不是中序遍历的性质。验证 BST、求 BST 第 $`k`$ 小元素等题目都利用这一点；对一般二叉树不能这样用。

## 6. 可迁移知识（Key Takeaways）

本题总结出以下可复用的方法：

1. **Inorder Traversal（中序遍历）**：在本题中，按“左 → 根 → 右”的定义递归输出。适用于二叉搜索树上一切依赖有序性的问题（验证 BST、第 $`k`$ 小元素、把 BST 转成有序链表）。限制：对一般二叉树，中序序列没有大小上的含义。
2. **Structural Induction（结构归纳）**：在本题中，对结点数做强归纳，归纳假设直接对应两次递归调用的返回值。适用于证明几乎所有树上的递归算法。前提是子树规模严格小于原树。
3. **Cost of Merging Returned Results（合并返回结果的代价）**：在本题中，每个值在它的每个祖先处被复制一次，总时间 $`\Theta(n + \sum d(u))`$。适用于分析任何“子问题返回容器、父问题合并”的递归。改进方法是传入共享的结果容器，让每个元素只写一次。
