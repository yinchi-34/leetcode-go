# 栈（Stack）

[English](./README.md) | 简体中文

术语遵循[共享术语表](../../docs/GLOSSARY.md)，数学记号遵循仓库的 [GitHub 数学书写规范](../../docs/GITHUB_MATH.md)。

本文是栈的总体笔记：定义、实现、代价，以及在题目中反复出现的使用模式。各应用题的题解只写“这道题怎么用栈”，栈本身的知识集中在这里。

## 1. 定义

栈是一种**后进先出**（LIFO, last-in first-out）的动态集合：删除操作取出的总是最近插入、且尚未删除的那个元素。它支持四个操作：

| 操作 | 含义 | CLRS 中的名称 |
|---|---|---|
| push(x) | 把 `x` 放到栈顶 | PUSH |
| pop() | 删除并返回栈顶元素 | POP |
| top() | 返回栈顶元素但不删除 | 无单独过程，直接读 `S[S.top]` |
| empty() | 判断栈是否为空 | STACK-EMPTY |

对空栈执行 pop 称为**下溢**（underflow）；数组实现中元素数超过容量称为**上溢**（overflow）。

## 2. 实现与代价

### 2.1 CLRS 的数组实现（§10.1）

CLRS 用数组 `S[1..n]` 和下标 `S.top` 实现栈：`S[1]` 是栈底，`S[S.top]` 是栈顶，`S.top = 0` 表示栈空。PUSH 先把 `S.top` 加 1 再写入，POP 先读出 `S[S.top]` 再减 1。每个操作都是 $`O(1)`$。

### 2.2 Go 中的写法

Go 没有内置的栈类型，惯用写法是用切片，切片末尾就是栈顶：

```go
st := []int{}             // 空栈
st = append(st, x)        // push
v := st[len(st)-1]        // top
st = st[:len(st)-1]       // pop（先用 top 读出再截断）
empty := len(st) == 0     // empty
```

代价说明：

- top、pop、empty 是 $`O(1)`$。
- push 在容量够时是 $`O(1)`$；容量不够时 `append` 会分配更大的底层数组并复制，单次是 $`O(k)`$（$`k`$ 为当前长度）。Go 运行时按几何倍数扩容（具体倍数是实现细节，语言规范没有规定），所以 $`m`$ 次 push 总代价是 $`O(m)`$，即**摊还** $`O(1)`$。这与 CLRS §17.4 动态表的分析是同一个论证。
- 能预估最大深度时，可以写 `make([]int, 0, cap)` 一次分配好，避免扩容。
- pop 只截断长度，不释放底层数组。元素是指针时，截断前可以把 `st[len(st)-1]` 置为零值，让垃圾回收能回收它。

### 2.3 空间

栈的额外空间等于**运行过程中栈的最大长度**，不是最终长度。分析复杂度时要先找出这个最大值由什么决定（例如括号串的最大嵌套深度），再给出最坏情况。

## 3. 常见使用模式

每种模式下列出“栈里存什么”和“何时适用”。后续有新题时补充到对应模式下。

### 3.1 嵌套结构：先处理里层，再回到外层

- **栈里存什么**：每个尚未闭合的层的信息，栈顶是最内层。
- **何时适用**：输入是嵌套的（括号、标签、递归定义的文法），且外层的结果要等里层算完才能确定。
- **为什么是栈**：最后打开的层一定最先闭合，这正是后进先出。
- **证明方法**：对“栈中第 $`i`$ 个元素表示第 $`i`$ 层当前的部分结果”写循环不变式，分 push、pop 两种情况证明保持。

### 3.2 表达式求值

- **栈里存什么**：操作数栈，必要时再加一个运算符栈。
- **何时适用**：带括号或带优先级的表达式；后缀表达式只需一个操作数栈。

### 3.3 单调栈

- **栈里存什么**：下标，且对应的值从栈底到栈顶单调。
- **何时适用**：对每个元素找左边或右边第一个比它大（或小）的元素。
- **代价**：每个下标最多入栈、出栈各一次，所以总时间 $`O(n)`$。这是 CLRS §17.1 聚合分析中 MULTIPOP 例子的同一个论证：pop 的总次数不超过 push 的总次数。

### 3.4 用显式栈代替递归

- **栈里存什么**：递归调用时本该保存在调用栈上的状态。
- **何时适用**：递归太深可能栈溢出，或需要在遍历中途暂停、恢复。CLRS 练习 10.4-3 要求用栈非递归地遍历二叉树，就是这种模式。

## 4. 什么时候可以不用栈

用栈的题目常有 $`O(1)`$ 额外空间的解法。去掉栈有两种不同的思路，要分清：

1. **栈退化成计数器**：如果入栈的元素彼此没有区别（例如只压入 `(`），栈的内容完全由它的长度决定，用一个整数记录长度即可。push 变成加 1，pop 变成减 1，empty 变成判断是否为 0。这是对同一个算法的等价改写，正确性证明不变。
2. **换一种计算方式**：如果栈中元素彼此不同（例如每层存一个不同的分数），栈就不能直接压缩成计数器。这时需要重新推导答案的表达式，让它不再依赖每层的具体值。这是另一个算法，要单独证明。
