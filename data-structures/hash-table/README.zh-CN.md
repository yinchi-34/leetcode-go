# 散列表（Hash Table）

[English](./README.md) | 简体中文

术语遵循[共享术语表](../../docs/GLOSSARY.md)，数学记号遵循仓库的 [GitHub 数学书写规范](../../docs/GITHUB_MATH.md)。

本文是散列表（也常叫哈希表）的总体笔记：定义、实现、代价，以及在题目中反复出现的使用模式。各应用题的题解只写“这道题怎么用散列表”，散列表本身的知识集中在这里。

## 1. 定义

散列表实现的是**字典**（dictionary）：一个动态集合，每个元素带一个关键字 `key`，支持三个操作：

| 操作 | 含义 | CLRS 中的名称 |
|---|---|---|
| insert(x) | 插入元素 `x` | HASH-INSERT / CHAINED-HASH-INSERT |
| search(k) | 查找关键字为 `k` 的元素，不存在则返回 NIL | HASH-SEARCH / CHAINED-HASH-SEARCH |
| delete(x) | 删除元素 `x` | CHAINED-HASH-DELETE |

只关心“某个关键字在不在”、不带附加数据时，字典就是一个**集合**。

## 2. 实现与代价

### 2.1 CLRS 的两种思路（§11.1、§11.2）

- **直接寻址表**：关键字取自小的全域 $`U = \{0, 1, \dots, m-1\}`$ 时，直接用数组 `T[0..m-1]`，`T[k]` 存关键字为 `k` 的元素。三个操作都是最坏 $`O(1)`$，空间 $`\Theta(|U|)`$。
- **散列表**：全域太大时，用散列函数 $`h : U \to \{0, 1, \dots, m-1\}`$ 把关键字映射到槽位。不同关键字落到同一槽位称为**冲突**，CLRS 用**链接法**解决：每个槽位挂一个链表。

设表中有 $`n`$ 个元素、$`m`$ 个槽位，**装载因子** $`\alpha = n/m`$。在简单均匀散列假设下，一次查找的期望时间是 $`\Theta(1 + \alpha)`$（定理 11.1、11.2）。只要让 $`m`$ 随 $`n`$ 增长、保持 $`\alpha = O(1)`$，三个操作的期望时间就都是 $`O(1)`$。最坏情况下所有关键字落到同一槽位，查找退化为 $`\Theta(n)`$。

### 2.2 Go 中的写法

Go 内置 `map[K]V` 就是散列表，装载因子过高时运行时会自动扩容（与 CLRS §17.4 动态表同一个摊还论证）：

```go
m := map[int]int{}        // 空表
m[k] = v                  // insert / 更新
v, ok := m[k]             // search：ok 表示是否存在
delete(m, k)              // delete
n := len(m)               // 元素个数
```

注意事项：

- **读不存在的键返回零值**，不会报错。所以 `map[int]bool` 当集合用时，`set[k]` 本身就是“`k` 在不在”，不用写 `_, ok`。值的零值本身有意义时（例如计数可能为 0），要用 `v, ok := m[k]` 区分“不存在”和“存在但为零”。
- **集合的两种写法**：`map[int]bool` 读起来直观；`map[int]struct{}` 的值不占空间，但判断存在要写 `_, ok := set[k]`。刷题时两者都可以。
- **遍历顺序是随机的**，每次运行都可能不同。答案不能依赖遍历顺序；需要有序时先把键取出来排序。
- 能预估元素个数时，`make(map[int]bool, n)` 可以一次分配好，减少扩容。

### 2.3 空间

散列表的额外空间是 $`O(n)`$，$`n`$ 是**不同关键字**的个数。用散列表换时间，通常就是用 $`O(n)`$ 空间把 $`O(n^2)`$ 或 $`O(n \log n)`$ 降到 $`O(n)`$。

## 3. 常见使用模式

每种模式下列出“表里存什么”和“何时适用”。后续有新题时补充到对应模式下。

### 3.1 存在性查询：把“找一遍”变成 $`O(1)`$

- **表里存什么**：已经见过的元素（集合）。
- **何时适用**：算法里反复问“某个值在不在”，原本要线性扫描或排序后二分。
- **典型变形**：查补数，例如两数之和中查 `target - x` 是否出现过，表里存值到下标的映射。

### 3.2 计数

- **表里存什么**：元素到出现次数的映射。
- **何时适用**：判断重排、找出现次数满足条件的元素、滑动窗口内的字符统计。

### 3.3 按规范形式分组

- **表里存什么**：规范形式到同组元素列表的映射。
- **何时适用**：要把“在某种变换下等价”的元素归到一起。关键是设计一个规范形式（canonical form），让等价的元素映射到同一个键，例如字母异位词排序后的字符串。

### 3.4 只从起点出发：避免重复扫描

- **表里存什么**：全部元素的集合。
- **何时适用**：答案由若干条互不相交的“链”构成（例如连续整数段），沿链扩展只需 $`O(1)`$ 的存在性查询。
- **做法**：只有当 `x` 是链的起点（`x-1` 不在集合中）时才向后扩展。这样每条链只被完整扫描一次。
- **代价**：内层扩展循环的总次数不超过元素个数，因为每个元素只属于一条链、只会被这条链的起点扫到一次。这是 CLRS §17.1 聚合分析的论证：不逐次估计内层循环，而是统计它在整个算法中一共执行多少次。

### 3.5 前缀和 + 散列表

- **表里存什么**：前缀和的值到出现次数（或最早下标）的映射。
- **何时适用**：统计“和为 $`k`$ 的子数组”一类问题，子数组和 $`= S_j - S_i`$，问题转化为查补数 $`S_j - k`$。

## 4. 什么时候可以不用散列表

1. **全域很小**：值域只有 26 个字母、或 $`0 \le x \le 10^5`$ 时，直接寻址表（数组）更快，也没有最坏情况退化。
2. **允许 $`O(n \log n)`$**：先排序，再线性扫描。只需 $`O(1)`$ 额外空间（不计排序本身），但会丢失原下标，要记录下标时需要额外处理。
3. **需要有序性**：要求“比 `x` 大的最小元素”之类的有序查询时，散列表做不到，要用平衡二叉搜索树或排序数组。
