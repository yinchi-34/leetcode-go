# 题目难度评分

本仓库使用三种模型描述题目难度：zerotrac 评分、力扣官方难度和四维评分。

三种结果并列记录，分别保留各自的含义，不互相换算或合成总分。

## 评分模型

| 模型 | 结果 | 评价对象 | 来源 |
| --- | --- | --- | --- |
| zerotrac 评分 | 数值型难度分 | 题目 | LeetCode Problem Rating |
| 力扣官方难度 | 简单／中等／困难 | 题目 | 对应题目的力扣页面 |
| 四维评分 | 四个维度各 1～5 分 | 指定约束下的具体解法 | 本文定义的标准 |

zerotrac 评分和官方难度在每道题中记录一次。四维评分需要注明解法；同一道题包含多种解法时，可分别评分。

## zerotrac 评分

引用 [LeetCode Problem Rating][zerotrac] 发布的难度分。数值越高，表示模型估计的题目难度越高。

根据作者的[原理说明][rating-method]，该模型使用参赛者的竞赛积分和比赛通过情况，通过 Elo 模型与极大似然估计计算题目难度。

设选手积分为 $A$，题目难度分为 $B$，模型预测的通过概率为：

$$
P(\text{通过}) = \frac{1}{1 + 10^{(B-A)/400}}
$$

计算时，根据实际比赛结果估计最能解释这些结果的 $B$。选手积分与题目难度分相同时，模型预测的通过概率为 50%。

本仓库直接引用发布结果，并保留数据来源链接。该项目的评分后端未开源；模型估计用于比较相对难度，不代表个人做题的实际成功率。

## 力扣官方难度

引用题目页面显示的官方标签：

| 标签 | 英文 |
| --- | --- |
| 简单 | Easy |
| 中等 | Medium |
| 困难 | Hard |

保留题目链接，按官方标签原样记录。同一道题采用不同解法时，官方标签保持一致。

## 四维评分

四维评分用于说明具体解法的难点，分别评价建模、知识、论证和实现。这是本仓库自定义的评价标准。

### 评分约定

- **评价范围**：明确题目、解法、输入约束、目标复杂度和实现语言。
- **基础要求**：默认读者熟悉 Go 基本语法、数组、切片、循环和函数。
- **取值范围**：各维度取 1～5 的整数，越高表示越难，分别记录，不求和。
- **评分依据**：选择最符合解法要求的等级，每项附一句具体理由。
- **一致性**：按解法要求评分，不因个人熟练程度变化直接调整分数。

算法名称、代码行数和时间复杂度本身不决定分数。例如，使用动态规划不意味着知识门槛一定高，存在整数溢出风险也不意味着实现难度一定高。

### 建模难度

从题目描述到算法模型，需要完成多少抽象与转换？

| 分数 | 标准 |
| --- | --- |
| 1 | 按题意直接模拟，无需额外转换 |
| 2 | 需要一次直接转换，如计数、排序或区间表示 |
| 3 | 需要发现关键关系，或设计能够表达问题的状态 |
| 4 | 需要多步转换，结合多个性质或模型 |
| 5 | 需要难以直接发现的构造、等价变换或复杂状态设计 |

评分理由应指出关键转换，例如“将连续区间求和转化为两个前缀和之差”。

### 知识门槛

理解并使用该解法，需要哪些前置知识？

| 分数 | 标准 |
| --- | --- |
| 1 | 基础语法、数组、循环和函数即可 |
| 2 | 需要一种常用结构或技巧，如哈希表、栈、前缀和 |
| 3 | 需要系统掌握一种算法，或组合使用少量常用知识 |
| 4 | 需要多种算法协同，或较专门的数据结构、数学知识 |
| 5 | 需要较长的前置知识链，或深入掌握多种专门知识 |

评分理由应列出实际依赖的知识，避免仅用“图论”“动态规划”等宽泛标签说明。

### 正确性论证难度

说明解法对所有合法输入都正确，需要多复杂的推理？

| 分数 | 标准 |
| --- | --- |
| 1 | 按定义或完整枚举即可直接说明 |
| 2 | 需要简单分类、局部关系或直观的不变式 |
| 3 | 需要明确构造不变式、归纳关系，或论证解的完整性 |
| 4 | 需要多个引理、较复杂的交换论证或多层归纳 |
| 5 | 需要较长的证明链、复杂分类或难以直接观察的全局性质 |

评分依据是推理的复杂程度，而非证明方法的名称。直接证明、反证、归纳、循环不变式和交换论证均可使用。

### 实现难度

在已经理解算法的前提下，将其写成正确的 Go 代码有多困难？

| 分数 | 标准 |
| --- | --- |
| 1 | 状态少，流程直接，边界简单 |
| 2 | 需要处理少量索引、分支或边界条件 |
| 3 | 多个状态相互配合，更新顺序、去重或递归边界容易出错 |
| 4 | 多种结构协同，状态联动复杂，需要协调处理多类边界 |
| 5 | 实现链条长，多层状态交织，局部修改容易破坏整体逻辑 |

评分理由应指出具体难点，如切片共享、状态更新顺序、边界包含关系或整数范围处理。

## 缺失值

| 状态 | 适用情况 |
| --- | --- |
| 待查询 | 尚未核对 zerotrac 数据或官方标签 |
| 暂无数据 | 已核对来源，但没有对应评分或标签 |
| 待评 | 尚未完成某个维度的评价 |

所有题目均保留三个模型的记录位置。缺失数据使用上述状态，不填 0，也不从其他模型推算。
